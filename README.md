# ЛР2. Трекинг плоского объекта по ключевым точкам

СКОИС. Степаненко В.П., P3432.

## 1. Теоретическая база

SIFT находит локальные особенности изображения в разных масштабах и описывает окрестность каждой точки вектором из 128 компонент. Масштаб и ориентация точки учитываются при построении дескриптора. Это помогает сопоставлять изображение объекта при изменениях размера и поворота. Сильное размытие и изменение ракурса снижают устойчивость.

Для каждого дескриптора эталона ищутся два ближайших дескриптора текущего кадра по расстоянию L2. Пара сохраняется, если первое расстояние меньше 0.75 второго. Так отбрасываются неоднозначные совпадения. Затем RANSAC оценивает гомографию и отсеивает пары, которые не согласуются с общим преобразованием плоскости.

Гомография задаётся матрицей 3×3 с восемью независимыми параметрами: $s(u,v,1)^T=H(x,y,1)^T$. Для её оценки нужны минимум четыре пары точек в невырожденной конфигурации. Углы эталонного прямоугольника переносятся через H в текущий кадр. Получается четырёхугольник, который учитывает перспективу.

## 2. Описание разработанной системы

`track.py` читает видео через OpenCV. Первый кадр служит эталоном; по умолчанию используется весь кадр, поскольку по условию он содержит крупное изображение объекта. Параметр `--roi X Y W H` ограничивает эталон прямоугольником. Для точного совпадения рамки с границами ROI нужно выбирать по объекту, исключая фон.

Каждый кадр сравнивается с неизменным эталоном: SIFT, BFMatcher, тест Лоу, `findHomography` с RANSAC и порогом 3 пикселя. Для рисования нужны минимум 6 inliers, их доля от сохранённых пар не меньше 0.25, конечный выпуклый четырёхугольник с площадью от 100 пикселей до четырёх площадей кадра. Чрезмерно большие координаты также отбрасываются. Это эвристики, их прохождение не доказывает правильность локализации.

При принятии результата рисуются зелёная рамка и подпись `Object`. При потере выводится LOST, старая рамка не переносится. Когда признаки снова видны, объект ищется заново. Оптический поток не реализован.

Нужны Python 3, NumPy и OpenCV с SIFT. Проверено на OpenCV 5.0.0 в существующем окружении. Команды из папки лабы:

```powershell
& 'C:\Users\User\PycharmProjects\DotaTrialsSolver\.dotavenv\Scripts\python.exe' track.py videos/mona-lisa.avi
& 'C:\Users\User\PycharmProjects\DotaTrialsSolver\.dotavenv\Scripts\python.exe' track.py videos/mona-lisa-blur.avi
& 'C:\Users\User\PycharmProjects\DotaTrialsSolver\.dotavenv\Scripts\python.exe' track.py videos/mona-lisa-blur-extra-credit.avi
& 'C:\Users\User\PycharmProjects\DotaTrialsSolver\.dotavenv\Scripts\python.exe' track.py videos/simple_track.avi
```

Исходные ролики из `../test-videos.zip` лежат в `videos/`, эта папка исключена из git. Выходной каталог задаётся `--output`, подпись - `--label` (для встроенного шрифта OpenCV используйте латиницу).

## 3. Результаты работы и тестирования системы

Реальный прогон 17.11.2026, размер 640×360, эталон - весь первый кадр:

| Видео | Кадры | FOUND | Среднее matches | Среднее inliers | Обработка, кадр/с |
|---|---:|---:|---:|---:|---:|
| mona-lisa | 558 | 315 | 29.30 | 21.98 | 24.99 |
| mona-lisa-blur | 558 | 296 | 25.22 | 17.95 | 25.11 |
| mona-lisa-blur-extra-credit | 558 | 281 | 25.12 | 17.53 | 25.04 |
| simple_track | 557 | 297 | 27.98 | 14.04 | 21.05 |

Для каждого ролика в `results/` записаны обработанное видео `*_out.avi` с кодеком MJPG, покадровый CSV и JSON со сводкой. Поле `matches` считает пары после теста Лоу, `inliers` - пары по маске RANSAC, `found` - результат всех проверок. Нумерация кадров начинается с нуля. Первый кадр тоже входит в статистику. Скорость учитывает чтение, обработку и запись после подготовки эталона.

Ссылки на результат: [обычный ролик](results/mona-lisa_out.avi), [размытие](results/mona-lisa-blur_out.avi), [extra credit](results/mona-lisa-blur-extra-credit_out.avi), [образец](results/simple_track_out.avi).

В размытых роликах получено меньше согласованных пар и принятых рамок. При этом эталоны извлекаются из каждого ролика отдельно, поэтому такое сравнение не изолирует только влияние размытия. Ручной разметки нет: IoU и ошибка углов не измерялись. Визуальное совпадение рамки с границами ещё нужно проверить, особенно при эталоне на весь кадр.

## 4. Выводы по работе

Связка SIFT и RANSAC отработала на всех приложенных видео и сохранила результаты для каждого кадра. В обычном ролике принято 315 рамок из 558; непрерывного сопровождения нет. При недостатке соответствий рамка исчезает, а при повторном обнаружении возвращается. Чтобы оценить качество границ, нужны просмотр результатов и разметка. Для завершения задания также требуется свой ролик и публикация исходника с этим README на GitHub.
